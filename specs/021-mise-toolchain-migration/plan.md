# mise Toolchain Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make `mise.toml` the single source of truth for this repo's tool
versions, then use that pin to unblock Go 1.27.1 and `ax-go` v0.6.0, absorbing
all nine open bot PRs into one branch.

**Architecture:** `mise.toml` pins `go`, `golangci-lint`, and `node`. The
Makefile keeps every target name and reads the linter version back out of
`mise.toml` via `awk`, so the two cannot disagree. CI installs from the same
file through `jdx/mise-action@v4`, which lets `ci.yml` drop both
`actions/setup-go` and `golangci/golangci-lint-action` and simply run
`make lint` — the identical binary a developer runs locally. A drift guard in
CI asserts that `go.mod` and `mise.toml` agree on the Go version.

**Tech Stack:** mise (tool version manager), `jdx/mise-action@v4`, Go 1.27.1,
golangci-lint 2.13.2, Node 24, `github.com/rshade/ax-go` v0.6.0, Astro 7 /
Starlight docs site, GitHub Actions.

**Spec:** [`specs/021-mise-toolchain-migration/design.md`](./design.md)

## Global Constraints

Every task's requirements implicitly include this section.

- **Go version is `1.27.1`, exactly.** It must be byte-identical in
  `mise.toml` (`go = "1.27.1"`) and `go.mod` (`go 1.27.1`). The Task 2 drift
  guard enforces this.
- **golangci-lint is `2.13.2`.** Pinned only in `mise.toml`. It must not
  appear as a literal anywhere else.
- **Node is `24`.** Pinned only in `mise.toml`.
- **`github.com/rshade/ax-go` moves v0.4.0 → v0.6.0.** Import boundary is
  unchanged and non-negotiable: only `config`, `schema`, and the transitive
  stdlib-only `contract` may be imported. Never import root `package ax`,
  which pulls OTel/gRPC/protobuf into the build.
- **No new direct third-party Go dependencies.** Constitution
  §Third-Party Dependencies.
- **Makefile target names do not change.** `build test vet fmt fmt-check lint
  ci tidy clean help` all keep their spelling. `make ci` remains the gate that
  `AGENTS.md`, `CLAUDE.md`, and `skills/*/SKILL.md` reference.
- **Conventional Commits.** Subject ≤72 characters, no trailing period.
  `.github/workflows/commitlint.yml` gates the PR title.
- **Never hand-edit `CHANGELOG.md`.** release-please generates it from these
  commit subjects, so the subject *is* the changelog entry.
- **Never bypass gpg signing.** No `--no-gpg-sign`, no
  `-c commit.gpgsign=false`. If signing fails, finish the commit by hand in a
  shell.
- **A human runs every `git add` / `git commit` / `git push`.** `AGENTS.md`
  forbids the agent from invoking them and `.claude/settings.json` denies them
  at the allowlist level. Commit commands appear in this plan as instructions
  for the operator, not as agent actions.

## Task 1: Pin the toolchain in mise.toml

**Files:**

- Create: `mise.toml`
- Modify: `Makefile`

**Interfaces:**

- Consumes: nothing.
- Produces: `mise.toml` with a `[tools]` table whose keys are `go`,
  `golangci-lint`, `node`. Task 2's drift guard parses `go = "1.27.1"` from it
  with `awk -F'"' '/^go =/{print $2; exit}'`, so **the `go` key must be at
  column 0 with spaces around `=` and a double-quoted value**. Task 4 must
  write the identical version string into `go.mod`.

- [ ] **Step 1: Create `mise.toml`**

```toml
[tools]
go = "1.27.1"
golangci-lint = "2.13.2"
node = "24"
```

Deliberately narrower than the sibling `ax-go` repo, which also pins
`actionlint`, `govulncheck`, and `pipx:specify-cli`. No Makefile target here
runs any of those, and pinning a tool nothing invokes would invent a contract
the Makefile does not have.

- [ ] **Step 2: Install the pinned toolchain**

```bash
mise install
```

Expected: downloads Go 1.27.1, golangci-lint 2.13.2, Node 24.x. This may take
a few minutes on first run.

- [ ] **Step 3: Verify mise's shims actually win on PATH**

```bash
mise exec -- go version              # expect: go version go1.27.1 ...
mise exec -- golangci-lint --version # expect: ... version 2.13.2 ...
mise exec -- node --version          # expect: v24.x.x
```

If `go version` still reports 1.26.7, mise is installed but not activated in
this shell. Either prefix commands with `mise exec --` for the rest of this
plan, or activate mise per
<https://mise.jdx.dev/installing-mise.html#activate-mise>.

- [ ] **Step 4: Add the version readback and `ensure` target to the Makefile**

Insert at the very top of `Makefile`, above the existing `.PHONY` line:

```make
# Tool versions are pinned once, in mise.toml. GOLANGCI_LINT_VERSION is read
# back out of that file rather than duplicated here, so this Makefile can
# never disagree with what `mise install` actually puts on PATH.
GOLANGCI_LINT_VERSION := $(shell awk -F'"' '/^golangci-lint =/{print $$2}' mise.toml)
```

Then extend the existing `.PHONY` line to include `ensure`:

```make
.PHONY: build test vet fmt fmt-check lint ci tidy clean help ensure
```

Then add the `ensure` target immediately before the `help` target:

```make
ensure:
	@command -v mise >/dev/null 2>&1 || \
		(echo "mise not found. Install: https://mise.jdx.dev/installing-mise.html"; exit 1)
	mise install
	@echo "Toolchain ready: go, golangci-lint $(GOLANGCI_LINT_VERSION), node"
```

Note the recipe lines use **hard tabs**, not spaces — make requires it.

- [ ] **Step 5: Add `ensure` to the `help` output**

In the `help` target, add this line after the `clean` line:

```make
	@echo "  ensure     — install pinned tools from mise.toml"
```

- [ ] **Step 6: Prove the readback works**

```bash
make -n ensure | tail -1
```

Expected output contains `Toolchain ready: go, golangci-lint 2.13.2, node`.

If it prints an empty version, the `awk` pattern did not match — check that
`mise.toml`'s line is exactly `golangci-lint = "2.13.2"` with no leading
whitespace.

- [ ] **Step 7: Deliberately break the readback, to prove it is live**

Temporarily change `mise.toml` to `golangci-lint = "9.9.9"`, then:

```bash
make -n ensure | tail -1
```

Expected: the message now reads `golangci-lint 9.9.9`. This confirms the
Makefile is genuinely reading the file rather than caching a literal. **Revert
`mise.toml` to `2.13.2` before continuing.**

- [ ] **Step 8: Confirm the full gate still passes on the new toolchain**

```bash

```

Expected: PASS. Go 1.27.1 is now compiling code whose `go.mod` still declares
1.26.5 — that is legal (a lower directive builds fine on a newer toolchain)
and Task 4 closes the gap.

If `make lint` fails here with findings that did not exist at Task 0 Step 2,
they are Go 1.27 / golangci-lint 2.13.2 findings. Fix them in this task and
note them in the commit body — isolating them here is exactly why the

- [ ] **Step 9: Verify whether the local PATH-shadowing workaround is obsolete**


- [ ] **Step 1: Rewrite the `ci.yml` job steps**

Replace the entire `steps:` block of the `ci` job with:

```yaml
    steps:
      - uses: actions/checkout@v7

      - uses: jdx/mise-action@v4

      - name: Verify go.mod matches mise.toml
        run: ./scripts/check-toolchain-drift.sh

      - name: Download dependencies
        run: go mod download

      - name: Vet
        run: make vet

      - name: Format check
        run: make fmt-check

      - name: Test
        run: make test

      - name: Lint
        run: make lint
```

Both `actions/setup-go` and `golangci/golangci-lint-action` are gone. That is
the point of the migration: CI no longer holds its own opinion about either
version, so a local `make ci` becomes a true predictor of CI.

- [ ] **Step 2: Create the drift guard script skeleton**

Create `scripts/check-toolchain-drift.sh`:

```bash
#!/usr/bin/env bash
# Fails when go.mod's `go` directive and mise.toml's `go` pin disagree.
#
# This is the check that would have caught ax-go raising its own go.mod floor
# to 1.27.1 — without it, that surfaces as an opaque "module requires go >=
# 1.27.1" build error far from its cause.
set -euo pipefail

go_mod=$(awk '/^go /{print $2; exit}' go.mod)
mise_go=$(awk -F'"' '/^go =/{print $2; exit}' mise.toml)

if [ -z "$go_mod" ] || [ -z "$mise_go" ]; then
  echo "could not parse a go version (go.mod='$go_mod' mise.toml='$mise_go')" >&2
  exit 1
fi

# TODO(Task 2 Step 3): compare $go_mod against $mise_go and exit non-zero on
# a mismatch, printing both values.
```

- [ ] **Step 3: Implement the comparison — REQUESTED CONTRIBUTION**

See "Your contribution" below. Implement the comparison at the `TODO` marker,
then make the script executable:

```bash
chmod +x scripts/check-toolchain-drift.sh
```

#### Your contribution

The comparison is four or five lines, and it is the only place in this plan
where a judgment call changes long-term behaviour. Three questions decide it:

**1. Exact match, or prefix-tolerant?** Today both files say `1.27.1` and
`[ "$go_mod" = "$mise_go" ]` works. But mise accepts a partial pin —
`go = "1.27"` means "newest 1.27.x" — and against `go.mod`'s `go 1.27.1` an
exact match would then fail spuriously forever. Tolerating prefixes costs you
the ability to catch a real 1.27.1-vs-1.27.2 drift.

**2. How much friction do you want from Renovate?** Renovate's `mise` manager
will open PRs bumping `mise.toml` to 1.27.2 without touching `go.mod`. A strict
guard turns every one of those into a red PR needing a manual `go mod edit`.
That is either useful pressure to keep the two in lockstep, or recurring busywork
— and which one depends on how often you want to think about it.

**3. Should a `toolchain` directive count?** `go.mod` has none today, but
`go mod edit -go=` can add one. If it appears, it is a third version string
that can disagree with the other two.

Implement at the `TODO` marker in `scripts/check-toolchain-drift.sh`. A strict
version looks roughly like:

```bash
if [ "$go_mod" != "$mise_go" ]; then
  echo "toolchain drift: go.mod says $go_mod, mise.toml says $mise_go" >&2
  echo "fix with: go mod edit -go=$mise_go" >&2
  exit 1
fi
echo "toolchain OK: go $go_mod"
```

The `fix with:` line matters more than it looks — it is what a future you, or
a reviewer looking at a red CI check, reads first.
